===========================================================================
 SmartPlant — Cómo levantar el sistema en otra computadora (Ubuntu)
===========================================================================

El proyecto tiene DOS mitades independientes:
  A) Backend  -> FastAPI + Postgres/Timescale + MinIO + Mosquitto (en Docker)
  B) Firmware -> ESP32-C3 (Arduino), sirve el portal web embebido

Levanta solo la que necesites. Nada de esto depende de macOS: en Ubuntu limpio
es más simple porque no chocan los puertos.

Dos archivos NO viajan con el proyecto (están en .gitignore) y hay que
recrearlos a mano en cada máquina:
  - pythonServer/.env                 (secretos del backend)
  - ESP32_controller/sensible.h       (credenciales del AP Wi-Fi del firmware)


---------------------------------------------------------------------------
 0. Traer el proyecto
---------------------------------------------------------------------------

  sudo apt update && sudo apt install -y git   # si usas git; si no, copia la carpeta
  # copia/clona la carpeta del proyecto y entra en ella
  cd automatedGreenhouse


---------------------------------------------------------------------------
 A. BACKEND (Docker)
---------------------------------------------------------------------------

1) Instalar Docker + Compose v2:

  sudo apt install -y docker.io docker-compose-v2
  sudo systemctl enable --now docker
  sudo usermod -aG docker $USER
  # cierra sesión y vuelve a entrar para que el grupo 'docker' tome efecto
  # (si no, antepon 'sudo' a los comandos docker)

2) Crear el .env (no viene en el repo):

  cd pythonServer
  cp .env.example .env
  # EDITA .env y cambia OBLIGATORIAMENTE:
  #   JWT_SECRET_KEY   -> cualquier cadena larga y aleatoria
  # En despliegue real cambia también POSTGRES_PASSWORD y MINIO_ROOT_PASSWORD.

3) Levantar el stack y crear el esquema:

  docker compose up -d --build
  docker compose exec backend alembic upgrade head

4) Verificar:

  curl http://localhost:8000/health        # -> {"status":"ok"}

  Servicios (puertos por defecto en Ubuntu limpio):
    backend    :8000   (API FastAPI; OpenAPI en http://localhost:8000/docs)
    db         :5432   (Postgres 15 + TimescaleDB)
    minio      :9000   (API S3)  /  :9001 (consola web, admin/admin123456)
    mosquitto  :1883   (broker MQTT)

  Comandos útiles:
    docker compose ps                      # estado
    docker compose logs -f backend         # logs del backend
    docker compose down                    # apagar (conserva datos en volúmenes)
    docker compose down -v                 # apagar y BORRAR datos (¡destructivo!)

--- OJO: puertos ---------------------------------------------------------
  Por defecto el stack usa 5432 (Postgres) y 8000 (backend). Si esos puertos
  están ocupados por OTRO proyecto (p. ej. contenedores 'dbjaguar'/'jaguar'),
  crea un pythonServer/docker-compose.override.yml LOCAL que los remapee. Ese
  override es local de cada máquina y NO forma parte del proyecto.
    -> En una máquina limpia usa 5432/8000 por defecto (sin override).

--- Nota de arranque -----------------------------------------------------
  app/settings.py debe tener  extra = "ignore"  en su clase Config. El .env es
  compartido con Postgres/MinIO (tiene POSTGRES_USER, MINIO_ROOT_*, etc.) y sin
  esa línea pydantic v2 aborta el arranque con "Extra inputs are not permitted".
  (Ya está en el código; solo tenlo presente si el backend no levanta.)


---------------------------------------------------------------------------
 B. FIRMWARE (ESP32-C3) — solo si vas a flashear la placa
---------------------------------------------------------------------------

1) Instalar arduino-cli y el core ESP32:

  curl -fsSL https://raw.githubusercontent.com/arduino/arduino-cli/master/install.sh | sh
  sudo mv bin/arduino-cli /usr/local/bin/
  arduino-cli config init
  arduino-cli core update-index
  arduino-cli core install esp32:esp32       # incluye el ESP32-C3
  arduino-cli lib install ArduinoJson        # v6

2) Permiso del puerto serie (típico en Ubuntu):

  sudo usermod -aG dialout $USER
  # cierra sesión y vuelve a entrar

3) Crear ESP32_controller/sensible.h (no viene en el repo). El firmware usa dos
   símbolos: apSsid y apPassword (los consume WiFi.AP.create en el .ino).
   Plantilla:

       #ifndef _SENSIBLE
       #define _SENSIBLE
       // SSID del punto de acceso que crea el ESP32 (la red "SmartPlant").
       const char* apSsid = "SmartPlant";
       // Passphrase WPA2 del AP: 8-63 caracteres. CÁMBIALA.
       const char* apPassword = "cambia-esta-clave";
       #endif

4) Compilar y flashear (ajusta el puerto; suele ser /dev/ttyACM0 o /dev/ttyUSB0):

  arduino-cli compile --fqbn esp32:esp32:esp32c3 ESP32_controller
  arduino-cli upload -p /dev/ttyACM0 --fqbn esp32:esp32:esp32c3 ESP32_controller

  Monitor serie (para ver los logs de printSystemData a 115200 baud):
  arduino-cli monitor -p /dev/ttyACM0 -c baudrate=115200

5) Usar el portal: conéctate a la red Wi-Fi "SmartPlant" desde el celular/PC;
   el portal captivo abre el formulario solo (gateway 192.168.4.1).

  Genera ESP32_controller/mainForm.h. Nunca se edita el .h a mano.
  Para validar el JS tras editar (opcional, requiere node):
    # extraer <script> y correr: node --check

Estoy haciendo un proyecto de esp32 c3 que controla un cultivo hidroponico. Las principales salidas son 3 pines para controlar ventilador, bomba y lampara led blanca, yotras 2 importantes son 2 pines pwm para controlar arreglos leds dimeables a 1KHz. Mi duda es la etapa de potencia, que componentes usar para poder activar relevadores y mosfets respectivamente. No se si las bobinas de los relevadores serán de DC o AC, y por eso aun no puedo decidir que tipo de optoacoplador elegir. Quiero algo que pueda conseguir facilmente, economico y que no necesite circuitos de control complicados, lo mismo para los mosfets. Lo ideal sería que pueda conseguirlos rapidamente con cualquier distribuidor autorizado, o que puedan ser suministrados con mis PCB's a traves del servicio de jlcpcb por ejemplo. Lo que venden localmente en mi ciudad, muchas veces está etiquetado como obsoleto con vendedores como mouser o digikey,

GEMINI

Para tu proyecto con el ESP32-C3, el principal reto es que sus pines digitales operan a 3.3V y tienen una corriente de salida máxima baja. Necesitas etapas de potencia que se activen con total seguridad a este voltaje y que estén disponibles en el catálogo básico (Basic Parts) de JLCPCB o distribuidores globales para evitar componentes obsoletos.
Aquí tienes la solución más económica, comercial y fácil de implementar, dividida por cada tipo de salida.
------------------------------
## 1. Etapa para los Mosfets (Tiras LED Dimeables a 1 kHz)
Para controlar arreglos LED dimeables mediante PWM a 1 kHz, no uses optoacopladores. A esa frecuencia, un optoacoplador común (como el PC817) es demasiado lento y deformará la señal, haciendo que los LEDs parpadeen o no apaguen por completo.
La mejor opción es usar un Mosfet de nivel lógico (Logic-Level) de canal N, diseñado para abrirse por completo con los 3.3V del ESP32-C3.

* Componente recomendado: AO3400A (Montaje superficial SMT, encapsulado SOT-23) o IRLZ44N (Si prefieres montaje de inserción Thru-Hole, encapsulado TO-220).
* Por qué elegirlo: El AO3400A es una "Pieza Básica" en JLCPCB, extremadamente económica y se activa totalmente con menos de 2.5V en la compuerta (Gate). Soporta hasta 30V y 5.7A, ideal para tiras LED de 12V o 24V.
* Circuito de control: Muy simple. Conecta el pin del ESP32 directamente a la compuerta (Gate) del Mosfet a través de una resistencia de 100 ohms (para proteger el pin). Coloca una resistencia de pulso a tierra (Pull-down de 10k ohms) entre la compuerta y GND para asegurar que los LEDs permanezcan apagados mientras el ESP32 se enciende.

------------------------------
## 2. Etapa para Relevadores (Ventilador, Bomba y Lámpara)
Para activar las bobinas de los relevadores, siempre debes usar bobinas de Corriente Directa (DC) (típicamente de 5V o 12V, dependiendo de la fuente de alimentación que uses para tu circuito). Controlar la bobina con AC complicaría innecesariamente tu PCB. Los contactos del relevador (la salida) sí controlarán los aparatos de AC (110V/220V) de tu cultivo.
Para proteger el ESP32-C3 de ruidos eléctricos provocados por la bomba y los motores, la optoaislación es altamente recomendada.
## Opción A: La solución clásica con Optoacoplador (Totalmente aislada)

* Optoacoplador: PC817 (o su versión SMD EL817). Es el más común del mundo, ultra barato y disponible en cualquier tienda local o JLCPCB.
* Activador de la bobina: El optoacoplador por sí solo no puede corriente suficiente para activar la bobina del relevador. Necesitas un transistor intermedio. Se usa el un transistor NPN común como el S8050 o 2N2222.
* Circuito de control: El pin del ESP32 enciende el LED interno del PC817 (usa una resistencia de 330 ohms). El transistor de salida del PC817 activa la base del transistor S8050, el cual finalmente energiza la bobina del relevador. Indispensable: Coloca un diodo de protección en paralelo con la bobina del relevador (como el 1N4148 o 1N4007) para absorber los picos de voltaje al apagarla.

## Opción B: Integrado Darlington (La más limpia y económica para JLCPCB)
Si no requieres aislamiento óptico estricto pero quieres ahorrar espacio y componentes:

* Componente recomendado: ULN2003A o TBD62003APG.
* Por qué elegirlo: Es un circuito integrado que contiene 7 canales de transistores listos para manejar relevadores. Ya incluye los diodos de protección internos. Puedes conectar los pines del ESP32-C3 directamente a las entradas del ULN2003, y las salidas directo a los relevadores de 5V o 12V. Es una pieza estándar global que jamás estará obsoleta.

------------------------------

# 2\. Para los relevadores: usa bobinas DC

Esta es probablemente la decisión más importante.

Un relevador puede tener:

- bobina de 5 V DC
- bobina de 12 V DC
- bobina de 24 V DC
- bobina de 120 VAC
- bobina de 230 VAC

Pero **para tu PCB yo escogería deliberadamente uno de 5, 12 o 24 V DC**.

Por ejemplo:

- TE Connectivity PCB Power Relay 5V DC CoilMX$61.72LionCircuits + others★ 5

Un relevador con bobina DC se puede controlar así:

```
              +12 V
                │
                │
             BOBINA
                │
                ├─────────|<|──────── +12 V
                │        Diodo
                │
              Drain
                │
             MOSFET
                │
              Source
                │
               GND
```

El ESP32 solamente controla el **gate**.

### MOSFET para la bobina

Aquí no necesitas nada sofisticado.

Por ejemplo:

- 2N7002
- BSS138
- AO3400A
- IRLML2502
- Si2302

De esos, **AO3400A sería uno de mis favoritos para tu proyecto** si quieres algo muy común y con bastante margen.

- AO3400A MOSFETMX$0.36Richard Electronics★ 5

El 2N7002 también es extremadamente común:

- MMBT7002K-AQMX$3.06DigiKey Mexico

# 3\. El circuito de cada relevador

Yo haría esto:

```
ESP32 GPIO
    │
   100Ω
    │
    ├──────── Gate
    │           │
    │         AO3400A
    │           │
   100kΩ       │
    │          │
   GND       Source
               │
              GND

+12V ──────── BOBINA ─────── Drain
                  │
                  │
             ┌────┴────┐
             │  Diodo  │
             └────┬────┘
                  │
                 +12V
```

El diodo va **en paralelo con la bobina y en polarización inversa durante funcionamiento normal**.

Por ejemplo:

- 1N4148 para bobinas pequeñas
- 1N4007 para algo más robusto
- SS14 si quieres un diodo Schottky SMD

Yo pondría **SS14 o 1N4007** si no tienes una razón concreta para usar otra cosa.

### Valores

Para cada MOSFET:

- `Rgate = 47–220 Ω`
- `Rpulldown = 47–100 kΩ`

Una combinación muy conservadora:

```
GPIO ─── 100Ω ─── Gate
                  │
                 100k
                  │
                 GND
```

El pulldown garantiza que el relevador permanezca apagado mientras el ESP32 está arrancando.

Esto es particularmente importante porque el ESP32-C3 tiene estados de GPIO durante reset/boot que no deberías utilizar como garantía de que una carga permanezca apagada. El C3 funciona a 3.3 V y sus especificaciones de GPIO son compatibles con este tipo de control; Espressif especifica, entre otras cosas, `VOH ≥ 0.8×VDD` y un límite de salida de corriente bastante superior a lo que necesitamos aquí.  Espressif Documentation+1

# 4\. ¿Necesitas optoacoplador para los relevadores?

**No necesariamente.**

Este punto suele complicar innecesariamente los diseños con ESP32.

Si tienes:

```
ESP32
 │
 │ GPIO
 ▼
MOSFET
 │
 ▼
Bobina 12 V
```

y compartes GND entre la fuente de 12 V y la electrónica del ESP32, no necesitas aislamiento.

Pero si tienes:

```
ESP32
      │
      │  aislamiento
      ▼
   potencia
      │
      ▼
  red eléctrica
```

entonces el aislamiento puede tener mucho sentido.

### Si quieres aislamiento

Un PC817/EL817 es una opción extremadamente común y económica.

- SHARP PC817MX$9.71JAK Electronics★ 5

También hay variantes SMD:

- PC817 SMDMX$3.60JAK Electronics★ 5

Pero **yo no pondría un PC817 simplemente porque "es buena práctica"**. Añade:

- opto
- resistor LED
- resistor pull-up
- posiblemente otro transistor
- más componentes
- más espacio
- más cosas que pueden fallar

Para tus MOSFET PWM de 1 kHz, además, tampoco veo una razón para meter un PC817 entre el ESP32 y el MOSFET.

# 5\. Tus dos salidas PWM de 1 kHz son otro asunto

Aquí sí recomiendo claramente:

**ESP32 → MOSFET → LEDs**

No:

**ESP32 → opto → MOSFET**

El ESP32-C3 tiene periférico LED PWM (LEDC), así que 1 kHz es una frecuencia perfectamente razonable para generar PWM.  Espressif Documentation

La etapa puede ser:

```
                    +V LED
                      │
                      │
                 LED ARRAY
                      │
                      │
                    Drain
                 ┌────────┐
```

# 6\. Pero aquí hay una pregunta MUY importante: ¿cómo alimentas los LEDs?

Necesito distinguir entre estas dos situaciones:

### Caso A — LEDs ya tienen driver de corriente

Por ejemplo:

```
24 V
 │
 Driver LED
 │
 LED array
```

Entonces puedes controlar el driver dependiendo de qué entrada tenga:

- PWM
- enable
- dimming
- 0–10 V

### Caso B — tu arreglo LED es simplemente LEDs + resistencias

Por ejemplo:

```
24 V
 │
 resistor
 │
 LED
 │
 resistor
 │
 LED
 │
 MOSFET
 │
GND
```

Entonces el MOSFET puede funcionar muy bien como interruptor PWM.

### Caso C — arreglo LED de alta potencia

Por ejemplo 20 W, 50 W, 100 W...

Aquí **no recomiendo simplemente conectar el arreglo a un MOSFET y una fuente de voltaje**.

Necesitas conocer:

- tensión de alimentación
- corriente
- potencia
- si los LEDs tienen resistencia
- si tienen driver de corriente constante
- corriente máxima deseada

Y el MOSFET se selecciona en función de eso.

# 7\. Para tus dos MOSFET PWM, AO3400A es una muy buena primera opción

Para una PCB económica y fácil de fabricar, yo empezaría investigando:

### AO3400A

Ventajas:

- N-channel
- SMD SOT-23
- muy común
- barato
- adecuado para control lógico
- funciona bien con GPIO de 3.3 V
- excelente para cargas pequeñas/medianas
- fácil de conseguir

Para cargas mayores, cambiaría a un MOSFET con menor `RDS(on)` y mayor corriente.

**No elegiría el MOSFET únicamente por "60 V / 30 A".**

Para este diseño importan mucho:

```
RDS(on) @ VGS = 2.5 V o 3.3 V
```

porque tu ESP32 no le está dando 10 V al gate.

Ese detalle es muy importante.

# 10\. ¿Y si la bomba o ventilador son AC?

Ahí cambia todo.

Si tienes:

```
ESP32 → MOSFET → bomba AC
```

**no.**

Un MOSFET N-channel convencional no es el interruptor adecuado para una carga AC de red.

Tendrías dos caminos principales:

### Opción 1 — Relevador

```
ESP32
 ↓
MOSFET
 ↓
bobina DC
 ↓
CONTACTOS
 ↓
AC
 ↓
bomba
```

Es mi opción favorita para un prototipo de hidroponía sencillo.

### Opción 2 — SSR/triac

```
ESP32
 ↓
opto
 ↓
triac/SSR
 ↓
AC
 ↓
bomba
```

Puede ser excelente para cargas AC, pero aumenta las consideraciones de diseño térmico, corriente de fuga, tipo de carga, cruce por cero, etc.

Para tu primera PCB probablemente elegiría **relevadores de bobina DC**.

# 11\. Sobre el optoacoplador y AC/DC de la bobina

Tu duda original era muy buena:

> "No sé si las bobinas de los relevadores serán DC o AC y por eso aún no puedo decidir qué optoacoplador elegir."

La solución es:

**no diseñes el circuito de control dependiendo de que la bobina sea AC o DC. Define tú el componente.**

Por ejemplo:

> "Mi PCB requiere relevadores con bobina de 12 VDC."

Entonces tu interfaz queda perfectamente definida:

```
GPIO 3.3 V
     │
    100Ω
     │
     ▼
 AO3400A
     │
     ▼
 Relay coil 12 VDC
     │
    GND
```

Y el **tipo de corriente de los contactos** es independiente:

```
Relay coil:       12 V DC

Relay contacts:   250 VAC / 10 A
```

Eso es precisamente lo que quieres.

## 13\. Hay algo que todavía NO cerraría

Antes de dibujar el esquemático definitivo, me faltan **5 datos fundamentales de tus cargas**:

1. **Ventilador:** ¿12 V DC, 24 V DC o 120/230 VAC? ¿Cuántos amperios?
2. **Bomba:** ¿12 V DC, 24 V DC o AC? ¿Cuántos amperios?
3. **LED blanco:** ¿qué voltaje/corriente?
4. **Los dos arreglos LED PWM:** ¿voltaje y corriente máxima de cada uno?
5. **¿Qué tensión tendrás disponible para potencia?** ¿12 V, 24 V, ambas?

Con esos datos puedo proponerte **el esquemático completo de las 5 salidas**, incluyendo valores de resistencias, diodos, MOSFET específico, protección contra transitorios, conectores y separación entre la parte de **3.3 V / baja tensión y 120/230 VAC**. También puedo orientarlo para que sea razonablemente compatible con el ensamblado de JLCPCB y evitar componentes que sean difíciles de conseguir.
